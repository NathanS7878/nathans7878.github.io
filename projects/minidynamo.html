MiniDynamo

A KV-cache-aware LLM inference router — a distributed Rust and Python serving system modeled on NVIDIA Dynamo.

RustTokioaxumPythonFastAPIPrometheus

91% cache reuse · 23% lower p50 time-to-first-token · higher throughput, against a round-robin baseline.

The problem

When many users hit an LLM server with prompts that share a common prefix — a system prompt, a document, a conversation history — the KV cache for that prefix can be reused instead of recomputed. But only if the request lands on the worker that already has it.

A round-robin load balancer scatters those requests across the pool and throws the cache away. The work of recomputing a prefix that another machine already holds is pure waste, and it shows up directly as time-to-first-token.

How it works

  • An async Rust frontend (axum on Tokio) exposes an OpenAI-compatible streaming API.
  • Each incoming prompt is tokenized and hashed into prefix-dependent blocks, so two prompts that share an opening share their leading block hashes.
  • The router maintains a mirror of which worker holds which cached prefix blocks and routes each request to the worker with the longest matching prefix — falling back to least-loaded on ties.
  • Requests are proxied to a pool of Python (FastAPI) model workers with streaming passthrough, so tokens reach the client as they are produced rather than after the full completion.

What I measured

A concurrent benchmark harness compares routing policies head to head on the same workload, so the only variable is the routing decision.

What I got wrong

The router's cache mirror could drift from reality. When a client disconnected early, the worker's actual cache state and the router's model of it diverged, so subsequent routing decisions were made on stale information — sending requests to a worker that no longer held what the router thought it held.

Prometheus instrumentation is what surfaced it: the cache-hit rate decayed over long runs in a way that didn't match the workload. A metric disagreeing with a mental model is a better bug report than any stack trace. Fixed by reconciling state on disconnect.

Limitations

  • Single-node worker pool, with no cross-node cache sharing. Scaling past one machine would need a distributed view of cache residency, which is a materially harder problem than the one solved here.
  • The prefix-block hash assumes deterministic tokenization. A tokenizer change invalidates the mirror's assumptions.
  • Benchmarks are on one hardware configuration. The 23% figure is what this workload did on this machine, not a general claim about cache-aware routing.
