nano-infer

A from-scratch single-GPU LLM inference engine with custom CUDA kernels — transformer inference without generate(), vLLM, TensorRT-LLM, or FlashAttention.

CUDAC++PythonPyTorch

Measured: inter-token latency stays flat at ~51 ms from batch 1 to batch 32. Decode is memory-bound, and that waste is what the engine is built to attack.

Status — honest version

Phase 0 (ground truth) is complete. The benchmark harness and the correctness answer key exist and are stable: CUDA-synchronized timing with warmup, run-to-run variance between 1.0% and 2.3%, reference logits captured from HuggingFace and committed to disk, and a HuggingFace baseline recorded on the target hardware.

Phase 1 onward — the engine itself — has not been built yet. The paged KV cache, continuous batching, the custom kernels, and quantization are designed but not written. There are no nano-infer performance numbers on this page because none exist yet, and a placeholder table with invented figures would undo the point of the project.

The problem

Token generation on a GPU is memory-bandwidth-bound, not compute-bound. Most of the win comes from moving less data, not from doing less math. This project goes one layer below the frameworks to see where the time actually goes.

The rule the project holds itself to: HuggingFace is used for weights and tokenizer download only. The forward pass, the sampling loop, and the cache are mine. No vLLM, TensorRT-LLM, FlashAttention, or xformers — those are what it benchmarks against.

HuggingFace generate() baseline. RTX 3070 (8 GB, Ampere sm_86, 448 GB/s peak bandwidth), Qwen2.5-0.5B-Instruct, fp16, 128 new tokens.

The observation that motivates the project: inter-token latency is flat at roughly 51 ms across every batch size, so tokens per second scales almost linearly with batch. The per-step cost is loading weights out of VRAM, and that is paid once per step no matter how many sequences are in flight. Batch-1 serving therefore wastes most of the GPU.

Planned and in flight

  • Paged KV cache and continuous batching — so sequences can join and leave a batch mid-flight instead of padding to the longest.
  • Fused kernels — RMSNorm, SwiGLU, RoPE, and an online-softmax decode attention kernel, hand-written rather than composed from framework ops.
  • INT8/INT4 weight-only quantization with a fused dequantize-matmul kernel, since moving fewer bytes is the whole game.
  • Benchmarks reported as achieved memory bandwidth against the card's 448 GB/s theoretical peak, rather than as a bare speedup multiple.

Limitations

  • The engine does not exist yet. Everything past the harness and the parity tests is unbuilt. This page will carry real numbers or none.
  • One GPU, one model, one machine. All figures come from a single RTX 3070 running Qwen2.5-0.5B. Results on an 8 GB consumer card do not necessarily transfer to datacenter hardware, where the bandwidth-to-compute ratio is different.
  • Small model, amplified overheads. A 0.5B model exaggerates per-step fixed costs relative to a production-size model, so speedups measured here would need re-checking at scale.
  • Quantization will cost quality, and that regression has to be reported with numbers rather than waved past.
